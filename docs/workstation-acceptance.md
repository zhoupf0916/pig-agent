# 工作台验收：消息与文件交付

本轮覆盖本地 Pig 工作台的消息发送、真实模型文件交付和任务结束状态；不代表 Docker/VM 隔离已经实现。

## 修复

- 普通消息与小队提示使用客户端 UUID，乐观显示和服务端 SSE 回传按同一 ID 合并。重复播放事件不新增消息；用户主动发送相同文字仍是不同消息。服务端拒绝已保存 ID 的再次提交。
- 防止同一页面重复触发发送，忽略切换会话后迟到的消息流。
- 明确真实桌面与工作区内 Desktop 子目录不同。提示模型遇到工作区外目标时说明限制并等待用户选择，不得创建替代位置后宣称成功。
- 设置说明本地命令运行在宿主机，工作区是文件访问边界；文件预览显示实际绝对位置。
- 回合结束时未完成的进行中步骤恢复为待处理，避免空闲会话仍显示正在执行。

## 已完成验证

- `pnpm test`：72 个测试文件、550 项测试通过；`pnpm build`：类型检查与生产构建通过。
- Chrome + 延迟模型：回复等待期间用户消息只显示一条；再次发送相同文字保留第二条，不按文字错误去重。
- 真实 DeepSeek：要求写入真实桌面时，报告未完成且没有创建工作区内替代文件；指定工作区内 `acceptance.txt` 时写入 `hello` 并读回验证，交付实际绝对路径。
- 真实模型验收使用独立 `data/live-acceptance`，报告保存在其 `report.json`；凭据只存在 gitignored 本地设置中。
- 等待用户决定的计划状态有自动化回归覆盖。模型对自然语言目标的遵守通过上述实测确认，不能视为操作系统级隔离保证。

## 用户验收步骤

打开 http://127.0.0.1:8797 并刷新页面，使用现有 DeepSeek 配置：

1. 新建会话，发送“你好”，在等待回复时确认仅一条用户消息；回复后再发一次“你好”，应有两条独立用户消息。刷新后数量保持一致。
2. 发送“在当前工作区新建 acceptance.txt，内容为 hello，并读回核对”。检查产物预览正文与绝对路径，确认磁盘文件一致。
3. 当工作区不是系统桌面时，要求在真实桌面创建文件。应说明当前工作区限制并等待选择，不应把工作区 Desktop 子目录文件当成真实桌面交付。
4. 需要操作真实桌面时，在设置中把工作区根目录改为实际桌面的完整路径，再明确重试任务；现有工作区不会被自动更改。

本机服务恢复命令：`DATA_DIR=./data/bf-acceptance PORT=8797 pnpm start`（先完成 `pnpm build`）。当前使用真实模型；旧交接记录中的 mock 模型配置仅代表当时的演示状态。
