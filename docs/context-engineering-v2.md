# 上下文工程与评测（2026-09-26）

## 目标与验收

长任务在有界输入中保留用户目标、纠正和可追溯证据，不改写转录、不扩大权限。默认策略由共享 contracts 提供，Pig、Codex 包装层、Cloud 跟进沿用相同入口。

先建立可重放基线，再修复：短历史误删、多项更正丢失、长消息中部召回失败、云端二次组装丢失新信息、系统预算越界。测试要求原始转录不变、当前请求完整、工具调用与结果成组、审批仍由执行状态机决定。离线评测和模型评测分别报告，不能用字符串保留率代表任务成功率。

## 参考与取舍

- Anthropic [Context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：有限注意力、压缩、结构化笔记、按需读取。采用目标/纠正/计划/证据分区和有来源的摘录；不声称本次实现了 Claude Code 的模型语义压缩。
- Anthropic [Agent evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)：区分轨迹与环境结果、重复试验。离线检查输入不变量；可选模型评测检查结构化最终答案，独立记录 token/延迟/错误。
- LangGraph [Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)：区分 thread checkpoint 与跨线程记忆。保留现有转录为权威数据，不把摘要变成持久事实，不引入第二套框架。

字符预算仍标明 estimated_chars，不能冒充供应商 tokenizer 或计费 token。先不加向量数据库，也不默认增加付费摘要调用；语义压缩会引入遗漏、额外费用和延迟，必须在评测证明收益后接入。长期记忆沿用现有来源、scope、有效期和撤回校验。本轮重点是工作记忆选择与评测基础，不是新增自动学习。

## 初步设计

1. 在完整的修复后消息可装入时直接使用，不生成摘要。系统/工具/预留预算本身超限则失败。
2. 超限时保留当前请求和最新完整工具组，再为工作记忆保留有界空间。
3. 摘录按用户更正、目标、最新计划、历史证据排序；来源、角色与截断标记一起占预算，按条装入，避免末尾粗暴切割丢失安全说明。
4. 检索大小写归一化，中文双字片段+英文标识符匹配，按匹配程度与新近程度排序；摘录围绕命中位置，避免只看消息开头。它是词法检索，不能判断语义矛盾。
5. 携带的历史摘要不是新指令；保留它的同时给新增遗漏消息补充摘录，禁止递归摘要扩张。
6. 固定旧版本源码作为离线基线；合成用例和验收断言公开，可重复执行、机器可读输出，禁止把固定规则评分称为 LLM 成功率。

## 实现位置与真实行为

- `packages/contracts/src/context.ts`：有界组装、中文/英文词法检索、历史原文投影。新策略默认接入原有 Pig、Codex 包装层和 Cloud 组装入口，无需开关。
- `apps/server/src/agent/tools.ts`、`runtime.ts`：新增 `recall_context`，根据 query 查找证据或 messageId/offset/limit 分页读取原文，单次原文最多 4000 字符；运行时注入当前 session 的消息访问器。模型不能指定账号或会话去读取其他记录。截断提示包含来源 ID；没有历史访问器时明确失败。
- 查阅原文不访问文件系统、不运行旧工具、不改审批状态。真正执行仍走原有取消/审批/沙箱边界。等待审批时也不会绕过阻塞。工具可以返回历史审批文字，但明确标注它不是当前授权。
- 控制面给 Runner 的输入本身是有界转录，因此云端工具只能读该次输入及运行中新产生的消息。**没有新增跨控制面的原始历史检索 API**；不能宣称能找回所有先前已丢出运行输入的全文。本机运行可读取当前 session 完整转录。
- 携带摘录二次缩减时，原始目标优先于可省略的旧摘录，新增用户更正另行加入。摘要不变成新持久事实。
- `apps/server/src/agent/evaluation/`：冻结旧策略、场景、评分和测试。冻结版本源自 `0e9f91e`，仅评测使用，运行时不导入。
- `scripts/eval-context.ts`：离线与显式模型对照入口；CI 默认运行无模型模式。

## 可复现命令

```bash
pnpm eval:context --trials 10
pnpm exec vitest run apps/server/src/agent/context-v2.test.ts apps/server/src/agent/context-tool.test.ts apps/server/src/agent/context-runtime.test.ts apps/server/src/agent/evaluation
pnpm check:architecture
pnpm typecheck
pnpm test
```

模型模式不读仓库 `.env`，必须在本机安全设置 `PIG_EVAL_API_KEY`、`PIG_EVAL_BASE_URL`（OpenAI 兼容 /v1 地址）、`PIG_EVAL_MODEL`。下面命令会产生真实模型用量，默认离线命令不会：

```bash
# 一个场景，每个策略3次，共6次调用
pnpm eval:context --model --case middle-evidence-50 --trials 3 --max-calls 6
# 全部合成场景，每个策略3次，共180次调用
pnpm eval:context --model --trials 3 --max-calls 180
```

模型模式交替策略顺序，输出长度上限 256 tokens、单次超时 60 秒，不自动重试。调用次数超出显式上限时在请求前拒绝；这不是总金额保证，实际费用取决于供应商价格。报告逐次写盘，记录完成状态、实际 token（供应商未返回则缺失）、延迟、结果和错误分类，不记录密钥、原始响应或原始错误正文。当前任务是受控 JSON 信息恢复，不是完整的写文件/部署任务评测；评分不接受仅在解释中提到正确答案。相同评分器对两种策略使用相同标准。模型模式中的系统评分任务提示是固定脚手架，不计入历史字符预算；真实 prompt_tokens 按供应商返回计量。

报告带 Git 版本、dirty 标识、实现 SHA256、场景 SHA256、Node 与系统信息，默认存于被 Git 忽略的 `data/evals/context-latest.json`。可用 `--out` 指定独立报告路径。新策略的离线失败或模型结果失败使命令非零退出；旧基线失败保留为对照。

这是 **10 类场景 × 50/75/100 条填充历史的变体**，不是 30 个独立真实任务，也不是模型成功率。重复组装用于时间分布，不构成模型随机性试验。新策略保留了更多证据，输入略增、词法检索开销也略增；不能宣传 token 成本下降或速度提升。旧策略失败集中在携带摘录的新更正、中英文长消息中部证据和短历史误压缩。

失败先行证据：新增最初 7 项上下文测试在旧版本全部失败；查阅工具测试在实现前 3 失败、取消用例沿用旧保护已通过；自审又发现二次缩减可能丢失排在长更正后的目标，复现失败后修复。没有删改已有有效验收断言。

实际集成验证：模拟 SSE 模型收到保留两项用户更正的请求；完整模型/工具循环按消息 ID 找回第 20000 字符后的证据，随后继续回答，原始工具输出没有被改写。另通过 loopback HTTP 服务运行评测 CLI 的两种策略、各两次调用，验证答案不泄漏、结果评分、usage 字段及密钥不落盘。此处返回的 usage 是模拟值，不能当真实 token 测量。

## 面试如何讲

1. **问题**：长任务并不是简单“窗口不够”，而是有限输入中遗漏用户约束、证据和来源；日志越多，关键消息越容易丢失。
2. **选择**：以原始转录为权威，模型输入只是投影；短记录不压缩，长记录分配近期工具组与有来源工作记忆的预算。用户更正优先，历史工具文字不能升级为授权。
3. **按需读取**：留下来源 ID，使用只读工具恢复证据，而不是重跑可能有副作用的命令；文件是否改变仍须重新读取。
4. **验证**：冻结旧策略，相同任务/预算/评分做配对对照；先看输入安全不变量，再看真实模型最终结果。合成集用于复现缺陷，后续需要真实轨迹与独立留出集验证泛化。
5. **取舍**：采用词法检索和确定性摘录，无额外 LLM 调用，便于重放与定位问题。它没有语义总结的泛化能力，也无法证明覆盖所有隐含约束；不把字符数叫 token，不把模拟测试叫生产效果。

可如实写入简历的表述：实现有来源的分层上下文选择与按需历史读取，建设版本化对照评测和 CI 门槛，在 10 类合成场景的 30 个历史长度变体上，将输入验收通过数从 18 提升至 30，并通过实际 Agent/工具循环验证原文恢复与转录完整性。不要写“真实任务成功率从60%提升到100%”。

## 尚未证明与下一步

- 没有执行真实付费模型对照；提供了可运行入口，不虚构任务质量、成本或 token 改善。
- 没有自动语义压缩、向量库、自动长期记忆学习或模型 tokenizer。已有稳定偏好来源/scope/过期/撤回机制继续有效，没有新增跨租户记忆。
- 词法检索无法理解所有同义表达；固定最多两条优先纠正及后续剩余空间无法保证任意长约束全部保留。仍可能需要模型调用原文工具核对。
- 没有做真实文件版本驱动的记忆失效；当前用来源提示和重新读取规则约束历史证据，不能称为自动内容校验。
- Codex 使用选中的上下文包装文本，但其原生工具与内部上下文不可观测，`recall_context` 仅在 Pig 循环（本机/Runner）注册。
- 下一步先补真实失败轨迹和独立留出集，再以同模型同预算测语义压缩候选；只有实测收益覆盖额外费用、延迟和遗漏风险才默认启用。
- 本次不部署、不推送，不影响线上服务。
