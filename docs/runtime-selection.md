# 运行时选型

日期：2026-09-23。给下一版执行内核做选择。下面只写公开文档里能确认的实现方式，不写绕过沙箱的步骤。

## 结论

客户端的安全和审批对齐 Codex：沙箱内的读写和命令直接执行，联网或显式打开「每次都问」才停下来。协同项目仍然不能关掉审批。

云端不按条命令起容器。Runner 维护固定数量的执行槽，控制面把任务调度进空闲槽；任务结束清空槽位再复用。定时计划以控制面为准，用每天、每周或每小时表达，可以在云端槽位执行，也可以由已登录的电脑领取，同一时刻只有一台设备会执行。

不要把内核换成 Codex CLI，也不要默认接 WorkBuddy 或完整云电脑。个人任务在沙箱里面可以自动执行；出工作区、联网、读密钥才单独确认。协同项目的写入和命令继续逐次审批。

## 我们现在怎么跑

本机 Pig 的文件和命令走操作系统沙箱：macOS 用 Seatbelt，Linux 用 bubblewrap 加 seccomp。沙箱打不开就拒绝。默认在沙箱内直接执行，联网仍逐次确认；可以打开「每次都问」。协同项目不能关掉写入和命令审批。

云端由控制面把任务调度到 Runner 上预先准备好的执行槽。槽位用完会清空再接下一件任务，而不是每条命令新起一个容器。定时计划存在控制面，设备来领取本机执行的那一部分。

## 同类产品怎么实现

### Codex CLI

执行分两层。[官方沙箱说明](https://learn.chatgpt.com/docs/sandboxing.md)把「能碰到什么」和「什么时候要问人」拆开。

- 隔离：macOS 用 Seatbelt。Linux 和 WSL2 用 bubblewrap，再加 seccomp，并关掉新权限。WSL1 会直接拒绝沙箱命令。`danger-full-access` 和 `--yolo` 是显式关掉沙箱和审批，不是日常模式。
- 审批：沙箱里的常规动作自己跑，离开工作区或要联网才问。一次批准可以是这一次、这一会话，或按命令前缀记住。前缀规则比「整句命令永远允许」稳。
- 网络：默认不出网。只打开网络、不走代理，等于直连全网。代理再按域名和方法限制；文档写明域名重绑定靠代理消不掉，还要下层防火墙。
- 秘密：`.env` 用文件系统拒绝，操作系统层读不到，不是只靠名单跳过。云端密钥只在安装依赖的阶段可用，推理阶段会拿掉。子进程环境变量默认并不会自动剥掉名字里带 KEY 或 TOKEN 的变量。
- 展示：桌面、终端和云端共用一套事件。一轮里的文字、命令和 diff 增量推过来；要审批时这一轮先暂停，等接受、拒绝或本会话允许。云端关了页面，任务还在。

值得学的是沙箱和审批分开、出网再加代理、密钥在操作系统层拒绝，以及一条事件流给所有前端。不该学的是把 Codex CLI 嵌回来，或把关掉沙箱当成默认。仓库里的 [Codex 运行时](codex-runtime.md) 描述的是已经从产品里拿掉的旧选项。

### Claude Code

[沙箱文档](https://code.claude.com/docs/en/sandboxing)和[权限文档](https://code.claude.com/docs/en/permissions)也是两套开关。

- 隔离：Bash 在 macOS 上用 Seatbelt，在 Linux 上用 bubblewrap，出网用 `socat` 转到代理，按域名放行。沙箱默认不强制。依赖缺失时会告警后继续无沙箱执行；只有打开 `failIfUnavailable` 才拒绝。还可以显式关掉沙箱再跑。Pig 不学这一种降级。
- 审批：权限模式决定要不要问。沙箱能接住的 Bash 可以自动放行；出边界仍要确认。可以按命令前缀记住「不再询问」。无人值守如果跳过全部提问，文档要求外面再套容器或虚机，并且拒绝以 root 启动。
- 秘密：默认沙箱仍可能读到家目录里的凭证。要单独拒绝 `~/**/.env` 一类路径。Pig 目前只按文件名跳过工作区里的 `.env` 和私钥。
- 展示：工具调用和 diff 跟在同一会话里，用流式事件。换模式是会话状态，不是换一个执行引擎。

值得学的是出网走域名代理，以及沙箱不可用就拒绝。整进程沙箱还是预览。

### Cursor Cloud Agent

[Cloud Agents](https://cursor.com/docs/cloud-agent)和[安全说明](https://cursor.com/docs/cloud-agent/security)写的是云端隔离，不是本机 Seatbelt。

- 隔离：每个 agent 一台虚机，里面是完整开发环境。运行面是 Firecracker 微虚机，和 Cursor 其他生产账号分开。虚机按生命周期删除。
- 审批：云端终端默认自动执行，靠虚机边界和出网域名限制兜底，人最后看草稿合并。本机沙箱如果建不起来，退回「执行前要审批」，不是静默改到宿主机。
- 并行：子任务可以要自己的工作区副本。云端子任务是另一台虚机、另一条分支，做完再由父任务合并。本地工作区不被拖死。
- 展示：进度、终端输出和产物流回网页或桌面。环境可以用快照启动，避免每次重新克隆和装依赖。

值得学的是「一台任务一个环境」和并行时不共享工作区。不该学的是云端默认自动跑所有命令：那依赖对方的虚机和出网控制，Pig 的协同项目还需要人点批准。

### WorkBuddy

腾讯的 WorkBuddy 是桌面工作台加云端托管。公开实现以[企业智能体](https://www.workbuddy.cn/docs/enterprise/adminguide/CloudAgent)和[腾讯云产品说明](https://cloud.tencent.com/document/product/1831/134407)为准。

- 执行位置：桌面端操作授权过的本机文件夹；企业托管 Runtime 在腾讯云上跑。用户电脑只发指令、收结果。
- 云端 Runtime：一个 Runtime 是一台云端 Linux 沙箱，带文件系统和终端，加上一份 Manifest。Manifest 声明身份、工作区、环境变量、技能和密钥。密钥走安全通道注入，不写成沙箱里的文件。
- 生命周期：空闲大约 10 分钟后休眠，再次访问再唤醒。可以做检查点和版本，回滚到历史状态。腾讯云文档还写了跨节点恢复、写时复制分叉、端口转发和预热池。这些是平台能力，不是我们能直接调用的开源组件。
- 展示：ACP 和 SSE 推流式输出和工具调用。侧边栏是任务，右侧是产物、文件、变更和预览。多个任务可以同时跑。
- 和 CodeBuddy 共用的文档写明：本机 Bash 在 Linux 上用 bubblewrap，在 macOS 上用 Seatbelt。权限模式包括默认询问、接受编辑、跳过询问。沙箱里的命令可以自动放行，越出沙箱要再确认一次。云端 Runtime 是否用微虚机，文档没写。

值得学的是持久沙箱、休眠、快照，以及密钥不落盘。桌面和云端的切换如果做成「做到一半搬到另一台机器」，状态迁移成本很高，第一期不要做。

### 千问办公

[产品简介](https://help.aliyun.com/zh/qwenwork/qwenwork-intro)写的是办公交付，不是代码沙箱的内部结构。

- 桌面端直接读本机磁盘上的文档、表格、图片和视频，处理完可以写回原路径。网页版不碰本机磁盘，用钉钉或手机号登录。
- 云端定时任务按时间跑，结果推到钉钉。浏览器自动化（点击、输入、采集）目前只在客户端。
- 企业 [Hooks](https://qwenwork.cn/docs/desktop/hooks) 由桌面客户端在工具执行前调用企业自己的 HTTP 服务。`PreToolUse` 可以拒绝这一次命令或文件操作。文档写明：连接失败、超时或非 2xx 时记录错误后继续原流程。这个 Hook 适合审计和策略，不能当成唯一隔离边界。
- 桌面有「安全工作环境」，声明任务在本机独立空间里跑、数据不出设备。文档没有写 Seatbelt、bubblewrap 或微虚机。电脑操控分每次询问、自动执行和禁用。云端容器沙箱写在千问 AI 平台的托管 Agent 里，和千问办公不是同一个入口。

### 千问 Sandbox 和无影 AgentBay

这两件东西不是千问办公本身，但是阿里云上能买到的执行环境。

- [千问 AI 平台 Sandbox](https://platform.qianwenai.com/docs/agent-infra/sandbox) 兼容 E2B。一个模板规定镜像、规格、挂载、网络和生命周期；一个实例是一次隔离运行，有自己的计算、文件系统和网络。镜像分代码解释器、浏览器、全能型。实例最长大约保持一天，空闲可以暂停并留下文件系统和内存。
- [无影 AgentBay](https://www.alibabacloud.com/help/zh/agentbay/product-overview/what-is-eds-agentbay) 按会话给云浏览器、代码空间、Windows 或 Linux 云电脑、云手机。云电脑用 VPC 和独立镜像隔离，权限可以限制网络和应用。过程可以通过流化协议看画面。适合操作 Excel、邮件和旧桌面系统。

拿它们当 Pig 的默认改代码内核会把产品变成壳：协议、审批和数据都在对方那边。以后如果要操作 Windows 办公软件，可以单接 AgentBay，不替换现在的 Pig 循环。

Kimi Work 公开的是本机文件夹授权和三档权限，没有写操作系统沙箱。Qoder（原通义灵码）写了本地终端沙箱和云端隔离容器，过程用 SSE。没有找到名为「文心一键」的独立执行沙箱。Devin 和 Manus 的公开说法都是每个任务一台隔离的云端机器。

## 三个方案

### A. 守住现在

继续 Seatbelt / bubblewrap，云端继续 Runner 容器里再套一层沙箱。

强度够本机使用。云端环境随任务结束消失，不能休眠后续跑，也不能给并行子任务复制一份磁盘。手感上，命令拆开之后审批变多。改动小，只适合作为这一周的底线。

### B. 两层运行时（建议）

本机保持操作系统沙箱。个人项目：沙箱内的读写和单条命令自动执行，联网、读密钥、离开工作区才确认。协同项目：写入和命令保持逐次审批。

云端一个任务一台微虚机或持久沙箱，里面仍跑现在的 Pig 循环。空闲休眠，唤醒后续跑。快照用来回滚，也用来分给并行子任务。密钥放在虚机外，按次注入，不写进工作区。

联网下一档对齐 Claude Code：命令默认无网，要出网时走带域名限制的代理。`http_fetch` 继续只连检查过的地址。

前端不另做执行器。服务端把文字增量、工具开始、参数、diff、审批和结束推成事件。卡片跟着事件长出来，审批贴在对应命令下面。并行时侧边栏同时显示多张任务卡，每张卡只看自己的虚机，合入前不共享工作区。

这和 Codex、Claude、Cursor、WorkBuddy 云端是同一档。代价是要做虚机调度和快照，不是再包一层 Docker。

### C. 外购执行面

本机或云端改走 WorkBuddy Runtime、千问 Sandbox 或 AgentBay。隔离和部分界面由对方负责，办公 GUI 用 AgentBay 更完整。Pig 的审批、技能、产物和账号会变成转发层。不选作主运行时。

## 方案 B 的顺序

1. 个人任务改成沙箱内自动、出边界才问。协同项目维持强制审批。这样拆命令不会把每次对话都变成一叠确认框。
2. 事件协议先补齐：文字增量、工具、diff、审批、结束。前端只消费这条流。
3. 云端把「一个 Runner 进程套沙箱」换成「一个任务一台可快照的环境」。第一期可以是长寿命的 bubblewrap 工作区加磁盘快照，微虚机放到快照和隔离都稳定之后。
4. 出网从「打开沙箱网络命名空间」改成代理。在此之前，网络开关保持默认关闭。
5. 并行子任务各拿一份快照和一条分支，父任务只接收合并后的产物。

方案 B 还没做。2026-09-23 收紧的是方案 A 的边界：不能关沙箱、地址检查和连接是同一次、协同项目不能关审批、Linux 沙箱联网和 macOS 对齐、密钥文件名不进模型。
