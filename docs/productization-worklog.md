# 产品化工作记录

## 目标与核心流程

同一 Web/Electron 工作台完成创建任务 → 选择本地/远端 → 观察执行与审批 → 核验成果 → 继续会话；管理员能管理模型、Runner、容量和队列策略。控制面以 PostgreSQL 为权威，支持至少两个实例与两个 Runner，并提供可复现实证。

- 现有本地平台 8890 含用户授权的真实 DeepSeek 渠道，8797 为用户工作台。不得将破坏性测试指向这些数据。
- 已有 594 个测试基线重新执行通过。浏览器 CUA 再次报 request-header policy 加载失败；改用隔离 Playwright 浏览器完成实际操作和截图，不以接口测试替代视觉验收。
- 单机问题：网关容器名硬编码、Runner 固定三槽位、无全局/用户/项目执行并发；节点缺独立心跳与启动代次；控制面过期 start 返回成功。

## 架构决策与假设

- 保留 Hono + PostgreSQL 队列、Docker Runner；短事务锁协调领取，不引入 Redis/Kubernetes。
- 执行副作用无法与数据库原子提交。不宣称 exactly-once；失联后不自动重放已启动任务，明确失败并由用户核验后重试。
- 测试使用新 Compose project、端口和凭据；不使用用户模型额度跑负载。
- 管理员的调度容量不能被 Runner 重启注册覆盖；节点容量与策略容量区分。
- 子任务：控制面、Web体验、管理后台并行；主代理负责 Runner、部署、浏览器与集成。

### 已发现、修复并复验的缺陷

1. 控制面切换的一次502导致审批任务失败：使用稳定领取receipt和有限安全重试；修后真实故障场景通过。
2. 旧Runner的恢复清理可能误删新代资源：先快照资源ID，再注册，清理仅针对旧快照；节点资源带instance标签。
3. Docker stop首次失败导致后续不再停止：区分停止请求与停止确认，重试并降级force delete；6个stub场景通过。
4. 设置小屏保存按钮被挤出：固定头尾与统一滚动区，390×844实测通过。
5. 新建/切换任务期间迟到PATCH覆盖当前任务：同步创建锁、配置保存锁、按当前session核对回写；延迟响应实测通过。
6. 新一轮审批入口仍指旧run：打开面板时跟随当前会话，手选历史停止跟随；真实follow-up通过。
7. 退出后迟到邀请响应泄露邀请码：登录代次校验；真实延迟响应→退出→释放响应回归通过。
8. 冷启动控制面重建时注册502让Runner退出：同一代次有限重试，鉴权失败仍立即退出；重建恢复通过。
9. 最终截图发现会话远端执行时顶部仍显示本机Pig：改为当前会话决定执行位置和审批说明，4个测试与重新渲染截图通过。

## 明确保留的边界

- 本机Docker多实例不代表宿主机/数据库/网关高可用，未验证跨主机延迟与生产容量。
- 不自动重放已启动副作用，用户核验后手动重试；上游真实模型请求不盲目重试以避免额外计费。
- 长期审批释放容器、对象存储与自动保留期、共享项目自动化、远端Codex、TLS/节点证书和签名自动更新未实现。当前备份可用，数据不会未经许可自动删除。
- Vite主包522.11KB未压缩（gzip 155.77KB），有体积告警；没有性能收益声明。
