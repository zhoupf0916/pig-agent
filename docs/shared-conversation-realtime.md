# 共享会话实时同步

控制面是会话与项目权限的权威。用户在同一共享项目中看到相同会话、按顺序追加的跟进任务和已提交的工作区版本；普通私有会话仍仅其所有者可见（平台管理员保留已有审计读取权限）。查看权不代表写入权，详情的 `conversation.can_write` 由项目角色计算。

`GET /v1/conversations/:id` 返回会话、执行轮次、消息及工作区版本。每轮 `author` 和用户消息 `author` 来源于控制面保存的运行所有者，不采信请求或模型输出的作者字段。模型上下文保留既有去工具调用、40 条消息上限；共享项目说明作为明确标记的用户背景注入容器，不能更改工具审批和权限。

`GET /v1/conversations/:id/events?after=<seq>` 为持续 SSE，可跨后续轮次订阅：

- `conversation_snapshot`：首次连接及执行状态、轮次、完整结果变化时的权威快照，字段同会话详情。
- `run_event`：`runId`、`seq`、`event`；SSE `id` 使用数据库持久序号，支持 `after` 或 `Last-Event-ID` 续传。
- 命名 `heartbeat`：维持空闲连接。
- `access_revoked`：会话权限、账户或当前登录失效后结束流。

已结束的运行不会关闭会话订阅。客户端应按持久序号去重，并以快照恢复最终消息；首次快照后的历史 token 不能重复拼入已完成的消息。每次轮询重新检查登录有效期、账户启用状态、当前角色及共享项目成员资格，包括已经建立的 Cookie 登录连接。事件活跃期约 100ms 轮询，空闲约 500ms；这是本地实现间隔，不是生产延迟承诺。

跟进复用现有事务、会话行锁、请求幂等键和最新父任务校验。同一父轮次的不同并发提交只能有一个成功，其他返回 409，客户端刷新后重新决定是否发送；不能静默丢弃或自动改写成新的轮次。

验证入口：`node scripts/smoke-cloud-realtime.mjs`。使用隔离 Docker 集群的两个控制面端口 8893/8894、两个 Runner 和模拟模型，检查多人上下文、作者、只读拒绝、幂等、并发冲突、跨节点 SSE、游标续传与实时撤权。结果保存在 `data/realtime-evidence/checks.json`；实际运行结果以该记录为准。

2026-09-22 实际集群验证通过，证据已保存到 `docs/evidence/realtime-2026-09-22/checks.json`。真实容器执行了三个轮次；两个控制面跨节点同步后续轮次和 token。数据库验证前两轮包含相同共享项目背景，第二轮模型输入包含第一位成员的原始消息。并发跟进实际返回一次 201、一次 409；成员移除与退出登录均使既有订阅收到撤权事件并关闭。此轮使用 Bearer 登录会话验证，浏览器 Cookie 验收由 Web 登录专项覆盖。无真实模型质量或生产规模容量结论。

## 桌面共享传输验收

`node scripts/smoke-desktop-shared.mjs` 使用临时独立 Electron 用户目录，在设置中连接隔离集群 8892。实际打开 `pig://app/#/shared/<conversation>` 已有共享会话，确认同一账户身份、会话 SSE 通过桌面代理返回 200；由另一客户端 API 追加下一轮，已经打开的桌面窗口实时显示新增消息与最终状态。打开成果面板后，分享链接为控制面的 HTTP 地址，而非 `pig://` 地址。前后本机会话数量均为 0，无需导入或复制云端会话。未申请系统电脑操作权限，未读取用户客户端数据；临时 Electron 退出后删除其专用目录。
