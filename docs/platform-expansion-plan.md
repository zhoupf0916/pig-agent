# Pig Agent 多端平台扩展计划

状态：待补充与确认，尚未开始本计划的功能实施。日期：2026-09-21。

## 目标和默认范围

交付用户 Web、Electron 桌面、管理后台、云端控制服务、真实容器执行五个协同模块。第一版面向邀请制内测，部署在单台 Linux 主机，本机 Docker Compose 可联调；验收基线暂定 10 个账号、3 个并发运行。桌面首期为 macOS，保留离线本地模式。

现有 Web / Electron / 本地服务可复用；当前 Cloud 只有消费端适配器、local-stub 和 mock，不能视为真实云执行平台。现有运行时字段混合了引擎与位置，需要兼容迁移。

## 模块与边界

| 模块 | 职责 |
| --- | --- |
| apps/web | 用户登录、空间/项目、会话、任务、文件、产物、模型和用量；云部署直接调用 cloud API，本地部署调用 server |
| apps/desktop | 复用 Web；本地目录、系统凭据、运行本地 server；登录云账号并选择本地或云执行 |
| apps/admin | 独立后台入口；账号/空间、模型渠道、运行队列、执行节点、模板、配额和审计 |
| apps/server | 继续负责本地能力，不改为多租户云服务 |
| apps/cloud | 身份权限、云数据、任务控制、事件、产物、模型代理及管理 API；首版为模块化单体 |
| apps/worker | 可信执行节点服务；领取任务租约、创建容器、收集事件、取消和回收，不对浏览器暴露 Docker |
| packages/agent-core | 从现有 Pig 循环提取可共享执行逻辑，通过接口注入文件、命令、模型、存储和事件 |
| packages/contracts | 版本化 API / 事件 / 执行协议；保留旧 Cloud 客户端兼容层 |
| packages/ui | 只提取确实被用户端和管理端复用的组件 |
| infra/ | Compose、数据库迁移、执行镜像、部署与备份脚本 |

执行位置与引擎分开：executionTarget = local/cloud，engine = pig/codex。首期支持本地 Pig、本地 Codex、云端 Pig；云端 Codex 在基础容器链路验收后接入。旧 runtime 字段迁移时保留历史会话可读。

## 核心链路

Web / Electron → cloud API → PostgreSQL 持久运行记录及队列 → worker → 每个云会话的独立工作卷和临时执行容器。后台通过 cloud 管理 API 查看和控制同一批运行。

首期使用 PostgreSQL 持久任务队列，不额外引入 Redis；认领、心跳、租约、attempt 和事件序号持久化。元数据存 PostgreSQL，大文件/快照/产物存对象存储，经存储接口接入；本机开发提供持久卷实现，部署采用 S3 兼容服务。模型网关初期作为 cloud 内部模块，通过运行级短期令牌访问。

一次会话可多轮执行，工作卷可保留，空闲容器回收。run 状态：queued → preparing → running → waiting_approval / succeeded / failed / cancelled；会话状态与单次 run 分离。follow-up 创建新 run 并使用该会话工作卷。重试创建新的 attempt，不能无条件重复执行已产生外部副作用的工具。

## 分阶段交付

### M0：契约与平台基础

- 落地执行位置/引擎分离，保持当前客户端兼容。
- 定义 user、workspace、membership、project、conversation、message、run、attempt、event、artifact、worker、model_channel、quota、audit 数据模型。
- 身份认证、邀请注册、登出/撤销会话；平台管理员、空间管理员、成员权限。
- 云端数据库、迁移、环境变量校验、健康检查和 Compose。
- 从本地执行器按真实需求提取共享代码，禁止直接跨应用导入。

验收：一键启动基础服务；两账号跨空间读取/修改均被拒绝；原有本地 Web 和桌面关键回归继续通过。

### M1：第一条真实云执行闭环

- worker 注册、心跳、任务租约、并发槽位和回收。
- Node/Python/Git 基础执行镜像；依赖准备与执行分别记录状态和耗时。
- 上传工作区归档及受控解包；校验文件大小、路径、符号链接和敏感文件规则。
- 真实 Pig agent 在容器执行，通过受限模型网关推理。
- SSE 事件持久化、断线补播；日志、文件差异、产物上传下载；批准/拒绝、取消与超时。

验收：上传示例项目 → 排队 → 容器写文件 → 执行检查 → 下载成果；取消确实终止执行；worker 掉线后租约恢复且旧 worker 不能继续提交结果；网关日志与任务日志可按 runId 对应。

### M2：用户 Web 云工作台

- 登录/邀请、空间与项目、云会话历史、上传文件或导入公开 Git 仓库。
- 展示排队、准备环境、执行、等待批准、终态；断网重连继续查看。
- 文件树、预览、下载、差异和运行报告；模型渠道选择和用量展示。
- 已有项目/专家/记忆/自动化等逐模块接云存储；不提供看似可用但只写本地的云入口。

验收：两个浏览器登录同账号能读取同一云任务与产物；不同空间隔离；浏览器关闭不影响云任务。第一条 Web 云任务页面随 M1 同步交付，再扩展其余页面。

### M3：管理后台

- 最小后台随 M1 提供运行列表、失败详情和取消；本阶段完善全部管理能力。
- 用户/空间管理、邀请、禁用；模型渠道配置、凭据加密、连通性测试。
- 队列与运行详情、节点在线状态、并发/CPU/内存配额、镜像模板管理。
- 模型 token 用量、费用估算、预算；管理员操作审计和任务关联日志。

验收：管理员能定位一次失败、停用异常节点并限制账号额度；后台权限由服务端校验；预算在入队/推理时执行，估算值和提供商实际结算区别显示。

### M4：桌面接入云端

- 本地/云模式明确切换，使用独立数据来源；本地历史不自动上传。
- 登录云账号；云任务与 Web 共用同一会话和事件 API。
- 显式上传选定项目快照、预览排除项；云成果下载到新目录或经差异审阅后应用。
- 保留本地 Pig/Codex 和系统加密凭据；改进开发热更新与启动诊断。
- 后续接入容器 Codex 时使用同一网关和运行级权限，不复制本机账号或凭据。

验收：桌面提交云任务 → 关闭桌面 → Web 看结果 → 桌面重新打开可继续；本地项目和云数据不会混淆或被无提示覆盖。

### M5：部署与发布验收

- Linux 部署说明、反向代理/TLS、备份恢复、任务及产物保留期、磁盘回收。
- Web / admin / cloud / worker 构建和镜像发布，固定镜像版本；本机 ARM 与 Linux AMD64 构建验证。
- 10 个账号、3 个并发任务、排队和预算、取消、断线重连、服务重启、隔离与恢复测试。
- 桌面版本管理和 macOS 打包；签名、公证及自动更新需独立发布配置。

验收：干净机器能按文档部署；恢复演练通过；Web 和桌面完成同一任务，后台可追踪并控制，磁盘和进程均能回收。

## 容器与凭据边界

- agent 容器不接触宿主 Docker socket、云数据库凭据、平台管理员令牌或长期模型 Key。
- 只有可信 worker 能管理执行节点的 Docker；cloud API 不接收任意 Docker 参数。
- 容器非 root、限制 CPU/内存/PID/磁盘/运行时长、根文件系统只读，写入仅限工作卷和临时目录；出站网络通过策略控制，阻止访问管理网络及云元数据地址。
- 模型 Key 留在模型网关；运行级短期令牌绑定空间、模型、预算和有效期。任意代码容器能读取自身令牌，所以令牌权限必须限制在该运行。
- 普通 Docker 首期限定可信邀请内测；对公网不可信代码开放前，执行节点与控制面分离并验收更强隔离方案。不能把普通容器宣称为完整的敌对多租户安全边界。
- 用户当前个人 DeepSeek Key 继续用于本机，除非明确授权，不上传为平台共享密钥。

参考：Docker Compose 支持声明式多容器启动（https://docs.docker.com/compose/）；Docker 官方说明了 daemon 权限和默认隔离的边界（https://docs.docker.com/engine/security/）。

## 暂不纳入首版

公开付费注册/支付、插件市场、移动端、多区域调度、Kubernetes、Windows/Linux 桌面包、无提示自动同步本地目录。保留后续扩展位置，但先完成各端真实链路。
