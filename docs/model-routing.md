# 模型网关：渠道故障转移与输出上限

## 渠道

管理端「模型渠道」里：

- **主渠道**：唯一一个处于启用状态的渠道，所有模型调用先走它。
- **备用渠道**：设置了备用顺序（1–9）的未启用渠道。主渠道失败时按顺序切换。
- **已停用**：既不是主渠道也不在备用列表里，不参与调用。

把一个渠道设为主渠道时，它会自动移出备用列表。没有主渠道时，网关使用部署环境变量里的平台密钥（`MODEL_API_KEY` / `MODEL_BASE_URL` / `MODEL_NAME` / `MODEL_MAX_OUTPUT_TOKENS`）；没有配置就是 mock 模式。

## 故障转移

网关按「主渠道 → 备用 #1 → 备用 #2 …」依次尝试，规则如下：

- 网络错误、30 秒内没有返回响应头（`MODEL_HEADERS_TIMEOUT_MS`），或上游返回 401/402/403/408/409/425/429/5xx，都会切换到下一个渠道。
- 400/404/413/422 是请求本身有问题，换渠道也一样会失败，所以直接返回，不切换。
- 只在响应头阶段切换。已经开始向 Runner 推流后不会再切换，避免同一回答混用两个模型的输出。
- 熔断：同一渠道连续失败 3 次后，30 秒内排到最后，仍作为最后的兜底（`MODEL_BREAKER_THRESHOLD`、`MODEL_BREAKER_OPEN_MS`）。熔断状态在每个网关进程内单独记录。
- Runner 断开（任务取消）时立即停止，不会再去尝试其他渠道。

每次调用的网关 span 上记录 `pig.failover.attempts`、`pig.failover.path`（各渠道及其状态）、`pig.channel_id`（实际服务的渠道）。指标 `pig_model_failovers_total{recovered}` 统计切换次数；10 分钟内切换 ≥ 3 次会触发 `model_failover` 告警（warning）。

## 输出上限

每个渠道有自己的输出上限 `max_output_tokens`（默认 4096，范围 256–32768）。同一个数用于三处：

1. 发给上游的 `max_tokens`：Runner 请求的值会被压到不超过它。
2. 额度预留：按所有候选渠道中「价格 × 上限」最高的一个预留，故障转移后不会超出预留。
3. 流式截断：网关按增量文本（正文、推理内容、工具调用）估算输出 token。中文约 1 字 1 token，其他文本约 4 字符 1 token。超过上限 25% + 64 时，判定提供商没有遵守 `max_tokens`：网关停止读取上游，补发 `finish_reason: "length"` 和 `[DONE]`，并记录 `pig.output.capped`，计入 `pig_model_output_capped_total`。

## 结算

- 优先按提供商返回的 `usage` 结算。由备用渠道完成的调用，按该渠道自己的价格计费，`model_usage.channel_id` 记录实际渠道。
- 流被截断、上游中途断开或 Runner 取消，导致拿不到 `usage` 时，按估算用量结算（`settle_kind = 'estimated'`）。以前这类调用会一直占着整笔预留额度。
- 所有渠道都失败时按 0 结算，释放预留。

## 验收

- `scripts/deploy/e2e-remote.sh` 默认检查渠道字段，以及网关 span 上是否带有上限和尝试次数。
- 设置 `PIG_E2E_FAILOVER=1` 会做一次线上切换演练：临时把一个无法解析的渠道设为主渠道，原主渠道设为备用 #1，跑一个真实任务，确认经备用渠道完成，最后在 `finally` 中恢复原主渠道并删除临时渠道。
