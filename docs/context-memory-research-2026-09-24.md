# 上下文与记忆治理：调研和技术选择

日期：2026-09-24。状态：方案已实施并完成本地机制验收；未发布线上，未进行真实模型长任务评测。

## 问题基线

- Pig runtime 的 `trimHistory` 以字符阈值删消息，辅助 `contextNote` 抽首条用户目标、计划和含审批词的工具结果；后者可能让旧执行事实看起来仍然有效。
- Cloud follow-up 先 `modelHistory` 去掉工具消息，再 `.slice(-40)`。多轮续接时，原目标与已执行工具事实会不可逆地从后续模型输入中消失，即使展示层仍有记录。
- Codex 适配器自行拼接最近 12 条文字、8 个工具摘要；这是 Pig 的截断策略，不能把它描述为 Codex 原生记忆。
- 本机 pin 只取最近 5 条，每条 200 字；云端取最早 50 条再限 16000 字，没有明确失效策略。双方必须保留原有作用域和协作隔离边界。
- 上一轮文件工作台/网络改动尚未提交；本轮不能覆盖它们。

## 公开资料及可借鉴之处

1. [OpenAI Compaction](https://developers.openai.com/api/docs/guides/compaction)：Responses 可按阈值生成压缩项，延续后续上下文。压缩项是 opaque 状态，并非可移植的用户记忆。当前 Pig 使用兼容 Chat Completions 的模型链路，不直接接此接口，也不把公开 API 文档当作 Codex 全部内部实现的证据。
2. [Claude Code memory](https://code.claude.com/docs/en/memory)：项目说明与自动记忆分开；简短索引与主题文件按需读取。记忆需要整理和删除陈旧条目，并非将整个历史永久塞进提示词。
3. [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：按需读取、压缩、结构化笔记分别解决不同问题；长上下文不等于可靠记忆。
4. [Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)：使用进度记录、明确的验收状态和启动时核验恢复工作；摘要不能替代实际验证。
5. [Codex Configuration Reference](https://learn.chatgpt.com/docs/config-file/config-reference)：公开了独立的记忆生成/使用开关、原始候选年龄、未使用时间、整合数量和资源余量限制，也有自动压缩阈值。这支持“记忆有生命周期、生成和使用分离”的设计；这些数值不直接照搬给 Pig。
6. [Run long horizon tasks with Codex](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex)：用规范、计划、验证和状态文件形成可回访的项目记忆。这是公开案例，不构成 Pig 长任务能力或容量的测试证据。
7. [Codex Memories](https://learn.chatgpt.com/docs/customization/memories)：记忆作为辅助回忆，必要规则仍放项目文档；后台生成会避开活跃会话，并受资源限制。本阶段保留用户管理记忆，不启动自动学习，以免把未完成工作和外部文本错误固化。

以上是原则参考，不宣称复刻任何厂商未公开的记忆打分、提示词或内部机制。此处 harness 指运行时编排层，不是另一个具体产品。

## 决策

采用现有 TypeScript 运行时与存储的轻量实现，不增加向量数据库、独立记忆服务或新的模型依赖。

| 层次 | 内容与权威 | 生命周期 |
| --- | --- | --- |
| 完整会话 | 原始用户消息、助手消息、工具结果，保留角色和来源 | 现有会话存储，不被压缩改写 |
| 单次上下文 | 当前请求、稳定指令、近期完整工具组、带来源的历史摘录 | 每次模型请求重新组装，预算包含系统与工具定义 |
| 持久记忆 | 用户确认的偏好与笔记，带作用域/时间/有效期 | 按作用域加载；过期不注入，可更新和删除 |
| 当前事实 | 当前文件、最新工具结果、审批系统状态 | 文件重新读取；权限由控制面/本机审批机制判定 |

第一阶段使用可解释的确定性摘录与完整工具分组，不引入额外模型摘要调用。原因：避免重复费用、摘要幻觉和另一个失败依赖。代价：不会理解所有隐含语义，不能承诺无限长对话无损记忆。以后若引入模型摘要，需单独建立摘要质量、费用、取消和失败降级评测。

上下文限制应保守估计并明确计量单位，不能把字符数称为精确 token。当前请求与必要指令超过预算时明确报错，不能静默删掉用户目标。不能把本机累计调用预算与单次上下文窗口混为一谈。

记忆保鲜不等于一律按天删除：用户稳定偏好可长期保存；文件内容、联网状态和任务审批属于易变事实，必须重新验证。撤回的记忆不能由摘要重新注入；共享项目不得继承私人记忆、私人专家或者他人的审批同意。

## 验收清单

现状基线：本轮改动前，`transcript.test.ts`、`user-data.test.ts`、`store/memory.test.ts`、`codex/prompt.test.ts` 共 23 项测试通过（4 个文件）。这些测试通过仍不能覆盖上面的长对话问题。
补充基线：Pig runtime 22 项、Codex runtime 2 项也通过。独立审查新增 `context-review.test.ts`，已实际捕捉请求被移到工具结果之后、推理长度漏算、正常用户文字误判为摘要、审批字样导致目标丢失、跨项目记忆范围和无效过期时间等失败；另外覆盖长修正要求的保留。验收依赖最终回归，不以初版辅助函数测试通过为完成。

- 长对话超出旧的 12/40 消息窗口，仍能传入原目标和最近修正；原始记录保持不变。
- 完整工具 call/result 配对；未完成和取消的调用不能在下一次模型请求中变成已执行事实或授权。
- 大工具结果可缩减，当前请求不被删；总预算包括系统和工具定义，超限有清楚错误。
- 连续云端 follow-up 不递归叠加摘要，保留来源；客户端不能伪造隐藏记忆。
- 过期/撤回记忆不注入；个人与协同边界不变；禁用记忆生效。
- 旧文件事实不冒充当前磁盘状态，人工修改后的工作区继续具有权威性。
- 调试信息记录预算与裁剪数量，不默认记录敏感正文。
- 针对性行为测试、架构检查、类型检查、全量测试和相关构建；失败与未验证内容分别记入实现文档。

## 实施分工与发布边界

Cursor 已在本仓库新对话实施运行时、协议、存储与测试；主代理负责资料选择、独立审查与最终验证。暂不提交、推送或部署，也不启动已关闭的本机 Docker。不使用真实模型反复跑测试；模拟请求载荷可以证明上下文机制，但不能单独证明真实模型的长期任务完成率。

后续记录见 `docs/context-memory-implementation-2026-09-24.md`（由实现方填写实际结果）。

## 可复现的离线测量

`pnpm exec tsx scripts/benchmark-context.ts` 构造 50、500、2000 次历史读取和最后一条用户修正。每组预热一次、测量 15 次，检查目标/修正存在且没有突破输入字符预算，输出本机平台、消息数、中位数和 p95。它只测上下文组装耗时和体积，不调用真实模型，不能据此声称任务成功率、模型延迟或生产并发能力提升。
