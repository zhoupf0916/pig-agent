# 统一工作台与控制面调度验收

日期：2026-09-21。环境：本机 macOS、Docker Compose、PostgreSQL、Pig 容器执行器。远端模型使用 mock；验证的是实际容器、工具和调度链路，没有调用个人模型密钥。

## 本批交付

- 原 Web / Electron 工作台每会话选择本地/远端位置及 Pig/Codex 引擎；配置保存在会话，修改默认值不改历史会话。远端目前仅支持 Pig。
- 自动化页创建远端计划，配置 cron、IANA 时区、启停和错过策略。控制面持久调度，客户端退出不影响触发。
- 调度以 owner 锁、计划行锁、唯一触发记录及原子入队避免重复；同一计划不重叠，超账号队列上限时记录跳过原因。
- 手动运行、创建与旧 Cloud 自动化迁移支持幂等。旧远端计划从本地定时器排除，避免双重调度。
- 原工作台内展示远端运行状态、回复、工具日志和成果下载。连接断开不取消任务；停止需要控制面确认。
- 本地会话中途退出后可重读远端状态与事件，恢复回复且不重复消息。控制面不可用时不假装停止成功。
- 管理后台查看定时计划，控制 Worker 排空/接单与 1–3 个并发槽位。并发限制由控制面执行，而非信任 Worker 请求数量。
- 数据库初始化用事务与 advisory lock 串行化，支持重复启动；任务、计划与产物保留。

浏览器验收发现并修复了转发 Fetch Response 的不可变 headers 与 Hono CORS 冲突。带浏览器 Origin 的集成测试现覆盖此情形。另修复轮询白名单丢弃远端计划字段的问题。

保留了一条“远端执行验收（手动）”示例计划，计划为空，不会周期性执行。自动故障测试创建的计划会软删除，历史运行与审计仍可见。

## 仍然明确的产品边界

本批不是正式公网多租户发布。远端计划只保存提示词，不自动上传本地专家、项目和文件。远端多轮仍使用新快照，尚未提供持久工作卷；跨设备完整会话/项目同步、正式账号与组织、审批恢复、模型渠道管理和云端 Codex 留在后续计划。远端默认模拟模型不能完成任意自然语言任务；真实模型需在网关单独配置。

操作入口及命令见 [本地运行说明](local-cloud.md)，剩余里程碑见 [实施计划](platform-expansion-plan.md)。

## 2026-09-21：会话连续性与平台管理

本机 Docker 实测：

- 连续两轮分别使用真实容器，初始文件及生成文件跨轮保留，版本可下载。
- 跟进幂等、过期父运行冲突、账号隔离；对话上下文移除无对应工具结果的 tool_calls，完整展示历史不受模型上下文截断影响。
- 10 个一次性邀请账号在 3 槽位 Worker 排队完成；重复兑换拒绝、每日额度拦截、退出后令牌失效；测试账号全部禁用。
- 模型渠道密文认证及脱敏验证；真实外部渠道未启用，个人 DeepSeek Key 未上传。
- 同一工作台恢复远端会话，审阅导入不写磁盘；预览后本地文件改变时拒绝覆盖。
- 数据库 dump 已生成，并在临时数据库完整恢复验证，原数据库保持不变。
- Electron 原生启动、加密凭据、流式对话、消息去重、Codex 本机运行和重启持久化通过。

实现边界详见 local-cloud.md，未实现项仍保留在 platform-expansion-plan.md，不能视为公开多租户生产发布。
