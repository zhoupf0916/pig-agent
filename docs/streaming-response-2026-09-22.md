# 云端流式响应优化 · 2026-09-22

## 已实施

- Runner 不再丢弃 token；首段立即入发送队列，后续增量按60ms合并，累计2048字符提前发送。完整消息、工具事件和执行结束前先排空增量，保持顺序和原事件ID重试语义。
- 控制面在最近2.5秒有输出时以100ms间隔查询持久事件，空闲回到700ms；补发积压分页不额外等待，心跳降为10秒。继续逐轮核验身份、授权与游标。
- 前端增加真实输出光标和“正在生成回复”状态，尊重减少动态效果偏好，最终消息替换临时文本。保留白蓝主题。
- mock模型现在每80ms产生最多4字符，用真实网关、Runner、控制面和浏览器验证渐进显示；没有调用真实模型。

## 验证

`pnpm cloud:build`、`pnpm test`（94文件635测试）、`pnpm product:smoke`通过。

本机Docker Desktop双控制面/双Runner、Chrome：一条模拟回复记录13个token事件、13次可见文本更新，首尾可见增量间隔1051ms。每个可见片段都是最终内容的精确前缀；两路SSE未造成重复，最终仅一条回复。实际控制面SSE按游标续传后拼接内容完全一致。完整创建、审批、重试、跟进、取消、下载和管理端回归通过。

证据：[真实流式过程截图](evidence/streaming-2026-09-22/live-stream.png)、[执行链路及测量](evidence/streaming-2026-09-22/flow.json)。最终又单独运行一轮真实容器跟进，确认输出中提示“正在生成回复”，并正常完成。

## 生效与边界

本地8890控制面/Runner在无活动任务时更新并恢复健康；8797网页和桌面静态资源已更新，刷新后生效。原配置、权限、任务与密钥保持。

100ms是活跃期轮询间隔，不是端到端时延保证。模型首字时间、容器启动和网络延迟仍存在；长时间静默后的第一条事件可能等待最多一次700ms轮询。活跃期数据库查询频率提高，本轮没有据此推断生产并发容量。未替换为WebSocket或伪造逐字动画。
