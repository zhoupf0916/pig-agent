# 项目、账号与执行权限升级

目标：用户在同一工作台中使用项目与项目协同；使用申请审批后的账号密码登录；项目具有明确工作区；权限选择真实影响执行。

## 验收与状态

- P0 账号：申请→管理员审批→密码登录→刷新保留→退出；未批准、禁用账号不能使用，密码不明文保存。（已实现并验证）
- P0 权限：云端保持运行容器隔离；网络访问必须绑定具体请求审批并防止访问内部网络；桌面明确本机/Docker边界。（已实现并验证）
- P1 项目：协同入口位于项目分支，不替换整个桌面壳；Web个人项目与协同项目共用任务界面。（已实现并验证）
- P1 工作区：本机项目绑定已存在绝对目录，新任务固定该目录；修改项目默认目录不改变已有任务。云端项目汇总会话文件版本，按会话恢复，不声称多人共享可写实时目录。（已实现并验证）

## 决策

保留现有 PostgreSQL 权限与会话模型。个人云项目使用 owner_id，无组织成员继承；组织项目继续以现有成员角色判断读写。云端工作区保持会话版本隔离，避免并发会话覆盖文件。账号密码替代面向用户的令牌输入，内部机器凭证保持兼容。沙箱关闭只适用于本机执行，云端运行容器始终隔离。

## 复核中发现并修复的问题

1. 桌面项目目录变更后，成果保存仍默认读全局目录：改为任务绑定目录，已加实际文件内容校验。
2. 项目详情异步加载覆盖刚输入的工作区：UI增加加载与请求身份保护，不重置同项目草稿。
3. 并发登录/退出可由迟到登录恢复凭证：增加最新操作代次和串行凭证写入，取消的远端会话撤销。

## 剩余边界

云端不提供关闭容器隔离；批准联网仅覆盖指定公网HTTPS GET，不开放任意shell出网或依赖安装。个人云项目的工作区按会话保存版本，不是并发共享可写目录。本机Docker开关控制命令执行环境，文件工具继续受工作区边界约束；关闭时shell用本机权限。历史任务无目录字段保留旧兼容行为。账号没有邮件找回密码/自助重申流程。验证为本机Docker集群和真实浏览器/Electron，未宣称公网容量或生产高可用。

后续可选工作：基于真实使用补账号找回与重新申请，以及有域名范围限制的依赖下载；不通过放开宿主机或默认公网来替代权限设计。
