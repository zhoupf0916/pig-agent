# 恢复完整 Web 工作台

用户纠正：保留原工作台导航、页面布局、专家和技能等功能；只在项目下面新增项目协同。此前 Web 入口直接渲染简化 CloudWorkspace，错误地绕开完整工作台。

## 实施结果

- Web 恢复完整原工作台外壳：工作台、项目、专家与技能、自动化、记忆、搜索、远端记录、设置。项目展开普通项目与项目协同分支。
- 专家和技能接入云端账号持久化、权限校验和 Runner 上下文；补齐控制面镜像遗漏的内置技能文件。支持手动创建和模型生成草稿。
- 设置和记忆保存刷新保留；设置真实影响新任务。私有记忆不会自动注入多人项目；跨作者续聊不会沿用上一成员的私有专家配置。网络与写入审批默认不降低。
- 自动化接回控制面调度；没有会话的运行可独立打开详情、审批、日志和成果，不再错误跳转聊天。
- Web 继续仅调用云端执行 API；客户端现有导航、数据和本机能力保留。未迁移或删除原数据。
- 修复切换账号后旧请求401误退出新账号的问题；旧账号成功响应也不能覆盖新身份。

## 真实验证

本地 8892 双控制面 / 双 Runner、PostgreSQL、模拟模型、真实执行容器。浏览器视口 1440×900 与 390×844。三份报告及选定截图保存在 [证据目录](evidence/workbench-restoration-2026-09-22/)。

- 完整导航、项目分支、专家/技能创建并用于新任务。
- 设置和记忆保存、刷新、账号隔离；旧身份延迟401竞态。
- 实际任务审批、容器写文件、查看成果、搜索命中并打开原会话。
- 自动化创建、立即运行、审批、容器完成、成果预览、暂停、历史和详情深链接刷新。
- 页面异常0；没有误调用本机执行API；手机无横向溢出。人工检查技能桌面、设置手机、执行审批和成果等截图。
- 全量测试111文件、689项通过；架构检查、工作区构建及 Cloud/Worker 类型检查通过。Vite仍提示主包超过500KB（约616KB，gzip约181KB），没有隐去该提醒。

## 实际部署

已重新构建并部署用户访问的 http://127.0.0.1:8890/ ，服务健康，保持原 provider 模式。正式本机环境专家、技能、设置、记忆、搜索和自动化接口均返回200，包含4个内置专家和7个内置技能。部署前确认没有执行中任务，并生成、校验本机数据库备份（2026-09-22T05-08-48.836Z.dump）；未重置账号或模型渠道。

## 边界

上述执行证据使用模拟模型和真实容器，不能推断真实模型质量或生产容量。模型生成草稿在未配置真实模型的测试环境明确报503，手动创建可用；其提供商解析/配额路径另有自动测试，本轮未产生真实付费模型草稿。执行详情只展示最近事件，完整边界见 [运行详情](cloud-run-details.md)。本机 computer use 和本机插件仍由客户端提供，不冒充云端能力。
