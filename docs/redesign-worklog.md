# 工作台重设计与正确性修复

起点：`bf41409`。上一版独立验收不通过；本记录不沿用上一轮“已验收”的结论。用户提供的两份验收文档保留原文。

## 产品与设计决策

核心路径：选择工作区 → 描述任务 → 观察执行 → 就地审批 → 核验来源明确的成果 → 继续任务。

- 仅一条常驻左栏：品牌、全局入口、当前任务分组、底部设置与收件箱；账号连接放在设置。任务列表属于此栏，不再叠加第二条任务侧栏。
- 主区标题栏桌面60px，手机56px；只显示当前页面/任务、真实状态、配置与成果入口。执行位置、引擎、审批和绑定项目归入任务配置。
- 新任务采用居中、适中宽度的输入工作区；工作区与配置邻近输入；无成果时不创建空检查面板。
- 对话按角色、执行摘要、待办审批和成果划分层级。审批在会话内显示可读的操作对象、文件内容/命令、影响范围；原始参数折叠。
- 成果检查器按需展开，桌面宽度可调、小屏为抽屉。所有远端文件以run/artifact身份读取，不隐式映射本机路径。日志与版本在任务上下文中访问。
- 设置为分组导航的大型工作面：模型、执行默认值、工作区、远端连接、外观、高级。保存前保留草稿，失败不清除输入，离开未保存内容有明确选择。
- 全站共享中性色、字体、边框、品牌色、状态色和控件尺寸；正文15px，辅助13px。浅色与深色均独立检查。管理端保持鉴权独立。

## 顺序与验收

1. F1完成结果可恢复幂等交付；F2产物来源；F3旧代注册不可复活。先建立能捕获原故障的回归，再修复验证。
2. 工作台与设置作为设计样板，1440×900、1280×800、390×844实际操作和截图自审。
3. 推广到项目、专家、自动化、远端记录、管理后台；Runner紧凑列表和筛选。
4. 同尺寸前后截图覆盖空态、执行、审批、成果、错误、设置、管理端，含明示UI夹具和真实mock容器流程。完整创建/审批/取消/重试/恢复/跟进/下载回归。

## 自审发现与再验证

1. 首轮手机审批按钮处于全局近全屏记录窗口底部 → 改为当前会话卡片，真实手机浅/深截图批准、拒绝和停止均可见。
2. 首轮设置导航标题被辅助说明挤成两行、次按钮无样式、双倍留白 → 分离导航主副文字、共享按钮尺寸并缩减重复间距，再跑全部六组截图。
3. 关闭未保存设置时嵌套 Escape 重新打开确认 → 修正事件传播和焦点行为；浏览器复现后通过。
4. 项目/专家等页面虽无横向溢出，390px 上详情仍被第二栏挤到约150px → 去除常驻第二栏，目录抽屉选择后关闭；实际创建和手机选择通过。
5. 搜索“清空”按钮被宽输入框挤成竖排 → 固定按钮不收缩，保持输入弹性；后续构建重新采样。
6. 无关页面残留当前任务错误条、长任务标题不可区分、审批中工具行仍显示进行中 → 限定任务错误作用域、标题两行、待批准单独状态；不只调整色彩。
7. 移动成果抽屉未完整限制键盘焦点 → 补充打开焦点、Tab 范围、Escape 与返回焦点，加入上下文实际操作检查。
8. F1/F3 初次独立数据库迁移发现顺序问题 → 修正后验证首次、重复迁移与历史代次回填；不靠已有数据库状态掩盖失败。

9. 严格节点故障测试发现停止的控制面别名落入宿主fake-IP DNS，审批POST返回502 → 隔离控制网络、限制DNS后备、改目录配置挂载并增加启动重载/健康探针。保留原严格断言重新通过；证据含原失败状态，没有用自动POST重试掩盖故障。

10. 最终组合浏览器发现重复选择同一成果版本清空文件列表 → 同值选择不再触发状态清空；来源、版本、下载和导入实际路径重新通过。
