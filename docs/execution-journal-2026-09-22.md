# 执行日志与成果交互整理

目标：默认关注回复、需要决策的审批、文件成果；排障信息仍可完整查询，不改授权或来源边界。

- 相邻已成功工具操作在会话中合并成可展开的摘要，失败、待执行与待批准操作继续直接展示。
- 两个远端日志入口共用执行步骤视图。每个工具调用合并开始/结束事件，错误独立显示；token、消息与同步事件不再逐条刷屏，完整原始事件放入诊断折叠区。
- 运行详情按实际工具步骤计数，最终回复可展开；运行标识移入详情。
- 成果保留版本选择、内容/对比/日志、来源、下载与显式审阅导入。来源说明压缩为一处，不混用本机同名文件。
- 成功审批立即更新工作台共享状态；旧轮询不能把已确认决定恢复成待审批，授权被领取后移除等待提示。

验证（隔离 8799 + 8892 mock 控制面/真实 Runner 容器，Chrome）：

- 5 个针对性单元测试通过，Web TypeScript 检查与构建通过。
- `data/journal-evidence/flow.json`：9 项真实会话流通过，涵盖审批、流式响应及去重、下载、刷新、续聊、拒绝重试、取消。
- `data/journal-evidence/journal.json`：真实运行 31 条原始事件显示为 2 项工具步骤，折叠与展开正常；1440×900 与 390×844 截图已目视检查，无横向溢出。
- 成果溯源回归通过：历史版本选择、本机同名文件隔离、快照下载、审阅导入；桌面和手机截图见同目录 `artifact-source-*.png`。首次运行因版本选择 label 改名超时，已恢复原 label 并重跑通过。

复现：在隔离验收服务运行时，先以 `PIG_FLOW_BASE`、`PIG_FLOW_EVIDENCE` 指定环境运行 `scripts/smoke-product-flow.mjs`，再运行 `scripts/smoke-execution-journal.mjs`；成果溯源复用 `scripts/smoke-artifact-provenance.mjs` 的 `PIG_REVIEW_BASE` 等参数。勿将写入测试指向用户工作区。
